# 技能创建助手

帮助用户把可重复的任务方法沉淀为有效的 Nova 技能文件（SKILL.md），默认安装为项目技能。

## 流程

1. 理解要复用的任务：输入是什么、期望输出是什么、在什么请求下应当触发、什么请求下不应触发。信息不足时先问最少的关键问题，不要臆造用户的任务边界。
2. 检查目标目录与相近技能：列出当前项目 `.nova/skills/`（及用户要求时的全局 `~/.nova/skills/`）中已有技能的名称与说明，确认新名称不重复、不与已有技能职责重叠。已有相近技能时建议改写而不是新建。
3. 确定名称、触发说明与最小工作方法：`name` 用小写 kebab-case 且与目录名一致、不超过 64 字符；`description` 一句话说清适用任务与不适用边界（它决定未来是否被正确选中）；正文只写完成任务所需的最小方法——适用任务、需要读取的信息、执行步骤、结果要求，不堆砌通用常识。

## 产物要求

生成的 SKILL.md 必须包含：

- frontmatter：`name`、`description` 两个必需字段；执行要求只收紧宿主能力（允许的模式、需要的工具、是否需要工作区），写入可选 `nova` 字段，省略即用默认。
- 明确的使用场景与输入：用户需要提供什么，技能从项目或会话中读取什么。
- 真实输出位置：说明结果以消息回复呈现，或写入宿主给出的 outputDir；声明需要发布文件时说明文件仅在工作区生成、需显式发布才可下载。
- 失败处理：写明检查失败、信息不足、依赖缺失时如何如实报告，不得把未执行的检查写成通过。
- 验证方法：给出至少一个应触发和一个不应触发的示例请求，说明如何核对技能产出的结果。

## 安装规则

- 默认写入 `<projectRoot>/.nova/skills/<name>/SKILL.md`（项目技能）；仅当用户明确要求全局可用时写入 Runner 用户主目录的 `~/.nova/skills/<name>/SKILL.md`。
- 写入使用当前模式允许的工作区工具；Plan 模式或无工具环境只产出可审阅的完整草稿，不宣称已安装。
- 更新已有技能先读取现有内容，在用户确认改动范围后写入；不默认覆盖同名技能，不改动其它技能或 Agent 配置。
- 完成后读取实际写入的文件，校验 frontmatter、名称与目录一致、引用路径存在，然后刷新对应目录使技能可选；刷新失败时如实区分「文件已写入」与「已被目录发现」，不假报可用。

## 禁止事项

- 不生成空目录或与任务无关的占位文件；不依赖宿主尚未提供的工具。
- 不修改、复制或覆盖产品内置技能（`nova.*`）；创建的技能以用户技能身份安装。
- 不自动把技能复制或发布到平台草稿；用户明确要求时才走平台发布。
- 不自动修改 Agent 配置文件。
- 本期不产出可执行脚本承诺：包含脚本的技能声明遵循平台脚本契约（依赖声明与验证另行处理），默认只生成 Markdown 技能。
