# Coding 场景测试

当前测试覆盖生产内核和插件的核心行为：插件装配与回滚、Agent Loop、严格工具执行、Task/Flow 调度、异步等待恢复、AI SDK 适配、压缩、Telemetry、MCP 桥接，以及真实文件和子进程 Coding 场景。模型网络使用受控 transport 或 scripted model，不把测试替身当作框架运行时。

## 执行

环境：Node.js >=22.18、pnpm 9.15.9，以及 PATH 中可用的 Git。本次初始化使用 Node 24.14.0。无需 API Key、数据库、队列服务或网络监听。

```sh
pnpm install --frozen-lockfile
pnpm typecheck
pnpm lint
pnpm build
pnpm format:check
pnpm check:boundaries
pnpm test
```

`pnpm test` 会自动发现并串行执行 `tests/**/*.test.ts`；当前包含 21 条核心与场景集成测试。`pnpm test:coding` 仍可单独运行三条真实 Coding 场景。

## 三条完整场景

| 场景             | 用户过程                                                           | 实际验收                                                                                       |
| ---------------- | ------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------- |
| 修复与追问       | 列目录 → 读代码 → 观察测试失败 → 修改 → 重新测试 → diff → 多轮追问 | 真实文件修复、3 项项目测试通过、工具只执行一次、消息配对、保留测试与用户备注                   |
| 并行 Coding Flow | 两个独立工作区并行修复 → 两者完成后汇总                            | 读取屏障证明真实并发、DAG 依赖顺序、输出绑定、汇总执行一次、工作区互不污染                     |
| 取消后继续       | 排队修复 → 开始长测试 → 取消 → 同会话重新验证                      | AbortSignal 到达真实子进程、关闭后才报告取消、保留已完成补丁、旧工具调用配对闭合、继续运行成功 |

## 真实与替身的边界

- 真实：生产 `createAgentKernel` 入口、插件装配契约、临时 Git 仓库、读写文件、Git diff、Node 测试与取消进程。
- 替身：模型网络响应，使用有限脚本重放模型调用。脚本不执行工具、不推进循环、不模拟 Task Engine。
- 目标项目故意使用加法计算总价；测试断言乘法、零数量、单件商品，不能通过修改测试“修复”。
- 并行测试使用可取消的屏障，不以 sleep 或固定耗时猜并发。
- 所有临时文件只写入本项目 `.tmp/coding-*`；原始样例只读。Git 使用场景专用配置，清理先停止内核和子进程，再校验并删除所分配目录。

fixtures 是受控测试辅助代码，不是可用于不可信代码的生产沙箱。真实 Coding 执行插件仍需实现路径、资源、权限、进程树和网络边界。

## 当前门禁与后续范围

当前成功标准是类型检查、Lint、构建、格式、依赖边界和完整测试全部通过；测试必须实际经过生产内核、插件、Task Engine 和真实文件/进程边界。

按顺序实现：插件生命周期与能力注册 → 会话/工具/Loop → 取消与历史配对 → 内存 Task 调度 → Flow 依赖和输入绑定。实现时持续运行同一批场景，不为通过测试直接修改 fixture 中的目标文件或绕过真实 runtime。

运行失败时不把异常转换成成功，不使用 skip/todo，也不在测试文件里实现 Agent Loop。真实供应商网络 canary 仍需显式提供凭据和 transport，未执行时不冒充已验证。

AI SDK transport、压缩、Telemetry、动态 Schema/MCP 和 Agent Task 恢复已有受控验证；3D、客服、RAG 的业务 client 不属于框架内置实现，按 [实现方案](./PLUGIN_AGENT_FRAMEWORK_PLAN.md) 的插件边界由宿主组合验证。
