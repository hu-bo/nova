# Nova 求职教练 Skill 设计

状态：P0 文本链路已实现，包含非 coding 会话配置、内置技能目录、输入与 checkpoint 快照、求职入口和消息版本展示。部署前需执行新增数据库迁移。文件解析、排版导出和跨会话档案不在本次范围内。

## 1. 选择：非 coding Agent 配置 + 求职 Skill

Agent 配置决定基础 system 指令、可用工具与执行策略；Skill 提供可复用的求职方法、交互规则和质量要求。Harness 负责执行循环、上下文、工具调度和会话恢复。复用执行内核，不代表继续沿用 coding Agent 的整套配置。

首版采用 **基于现有 `chatProfile` 的非 coding Agent 配置 + 一个内置 `career-coach` Skill**，产品显示名为「求职教练」，提供简历修改、模拟面试两种模式。两种模式共用候选人的经历事实，避免简历写了一套、面试又准备另一套。

| 层次 | 首版职责 | 扩展条件 |
| --- | --- | --- |
| Harness 内核 | 执行循环、模型调用、上下文、工具调度 | 复用既有机制 |
| Agent 配置 / 宿主 | 中性基础 system、工具集合、执行权限、会话保存 | 宿主明确选择，不能由技能正文切换 |
| Skill | 岗位分析、经历挖掘、简历改写、面试追问、复盘标准 | 方法和输出要求变化时更新技能 |
| 求职产品界面 | 普通会话中的技能选择与任务建议 | 需要跨会话档案、多个岗位版本、训练历史或语音面试时增加产品能力 |

专用入口可以复用同一执行引擎，不需要创建新的执行服务。跨会话保存、语音、提醒等能力需要宿主支持，增加提示词无法直接获得这些能力。

### 当前源码中的提示词边界

- `packages/coding-harness/src/configuration.ts` 优先使用显式传入的 `profile`，否则根据是否传入 Runner 选择 `codingProfile` 或 `chatProfile`。这些 profile 不会自动叠加；计划文件门禁仅在所选 profile 声明 `plan` 时安装。
- `apps/nova-server/src/modules/runs/nova-runtime.ts` 显式传入自己组装的 `profile.systemPrompt`，因此不能简单认定所有 `codingProfile` 内容都进入了 Nova。当前自定义 profile 也没有声明计划文件门禁。
- 但 Nova 当前基础指令仍包含检查工作区、Plan/Build，以及在相关条件下的项目指令、Runner 命令说明、Spec 和 Goal 指令。即使没有工作区，也仍会拼入基础身份与执行模式指令。
- `packages/harness/src/plugins/skills/index.ts` 把技能正文作为 `role: user` 的上下文贡献注入。它不替换 system，也不撤销已注册的工具和策略。

因此不能仅添加一份求职 Skill，并指望它覆盖 coding 基础指令。落地前需由宿主分别组装 coding 与非 coding Agent 的基础提示词和工具集合；求职方法继续留在 Skill，避免把同一套业务规则复制到 system 与技能中。

## 2. 用户流程

### 简历修改

输入现有简历和目标 JD；没有 JD 时接受岗位方向，先给通用诊断。沿用用户已经提供的背景，只追问影响改写的关键缺口。

1. 提取岗位要求，区分明确必需、偏好和未说明的信息。
2. 从材料整理经历事实：负责范围、采取的行动、技术或方法、结果，以及各项信息的来源。
3. 对照岗位逐项列出已有证据与缺口。区分「材料没写清楚」和「用户尚不具备」，不能从简历缺失直接断言能力缺失。
4. 针对重要缺口追问，例如个人贡献、关键决策、验证方法。可以询问指标，但不强求每段经历都有数字。
5. 输出问题优先级、原文与改写对照、修改理由和完整简历草稿；把待确认内容放在草稿之外。
6. 为改写后的重点经历附上可能被追问的内容，检查用户是否能解释每项主张。

无 JD 时可以立即润色；有 JD 时做针对性取舍。匹配结论须对应岗位要求和经历证据，不输出没有依据的 ATS 分数或录用概率。

### 模拟面试

输入沿用简历与目标岗位，再确认必要的面试类型，例如技术面、项目深挖或行为面。用户只想练一道题时直接开始。

1. 根据岗位重点和简历中的主张形成内部考察计划。
2. 每轮只问一个问题，等待用户作答，根据回答决定追问或换题。
3. 优先追问责任边界、决策理由、替代方案、实际结果与复盘；技术题结合目标岗位的深度要求。
4. 默认陪练模式：回答与必要追问结束后给反馈。用户选择仿真模式时，集中到结束后复盘。
5. 用户结束、跳过问题或达到约定时长/题数时收尾，不因答得不好反复阻止结束。
6. 复盘指出回答中具体的有效证据、遗漏或错误，给出基于真实经历的改进示例和下一次练习重点。

反馈使用「已体现 / 部分体现 / 尚未体现」描述本次回答的表现。单次回答不直接代表候选人的整体能力。

## 3. 事实与会话状态

Skill 规定怎么使用信息；宿主决定信息保存多久以及如何恢复。首版可以只依赖当前会话，不要求新建候选人数据库。

| 信息 | 内容 | 更新原则 |
| --- | --- | --- |
| 经历事实 | 用户提供的经历、负责范围、成果、来源及冲突 | 用户补充或纠正后更新；旧简历是来源材料，不能反向覆盖新确认的信息 |
| 目标岗位 | JD 原文、岗位要求及其解释 | 按岗位分别保存，推断与 JD 明文分开 |
| 简历草稿 | 从经历事实针对某个岗位派生的表达 | 改写措辞不自动成为新的经历事实 |
| 面试记录 | 已问问题、原始回答、追问、反馈、待练项 | 从实际问答形成，不能把参考答案记作用户已经掌握 |

来源明确不代表已被独立验证。遇到两份材料冲突时指出具体字段，确认前不自行选择更亮眼的版本。

## 4. 首版范围与验收

首版支持文本简历、粘贴的 JD、文字面试与消息形式的复盘。文件解析、排版导出和长期档案作为宿主能力另行接入；技能正文不承诺不存在的工具。

| 场景 | 预期行为 |
| --- | --- |
| 用户只给简历，没有 JD | 开始通用诊断，说明定向取舍需要岗位信息 |
| 用户说「帮我写得厉害点」，没有成果数字 | 改善表达并追问证据，不添加虚构指标或扩大负责范围 |
| 用户说「项目是团队做的，我只负责接口」 | 围绕接口设计、协作和实际贡献改写，不变成整个项目负责人 |
| 模拟面试回答空泛 | 围绕刚才回答追问具体场景，不提前给完整参考答案 |
| 用户纠正某项经历 | 后续简历和面试都采用纠正后的事实 |
| 用户说「结束面试」 | 依据已有问答复盘，不补造未发生的问答 |

接入沿用 [产品 Skills 设计](nova-skills.md) 的运行边界。现有 Skills 插件支持显式注入 Markdown；P0 已接入内置技能目录与逐条选择，自建技能管理与文档产物链路留待后续。技能正文、产品交互与运行接入分别验收。

## 5. Nova 产品落地

### 5.1 产品入口与连续对话

首版提供「求职教练」入口，创建使用非 coding Agent 配置的普通聊天。该会话的技能选择中展示「求职教练」，并提供「修改简历」「模拟面试」两条任务建议，点击后填入可编辑的开场文本，用户补充材料后发送。

```text
进入「求职教练」 / 已使用非 coding 配置的普通聊天
  → 使用非 coding Agent 配置，选择「求职教练」技能
  → 修改简历：粘贴简历，按需补充 JD
    或模拟面试：提供已有材料，选择陪练或仿真
  → 在同一会话继续修改、回答或复盘
```

- 输入框保留可移除的「求职教练」标签；每次发送都显式提交技能和精确版本，包括面试中的每次回答。标签可以在当前交互中保留，服务端不从上一条输入推断选择。
- 用户未提交技能时，这次输入按普通聊天处理；历史中出现过技能不能替代本次选择。消息记录显示实际采用的技能版本。
- 「修改简历」「模拟面试」「陪练」「仿真」首版作为用户指令进入会话，不增加与对话内容并行维护的业务阶段字段。切换任务继续采用同一份经历事实。
- 每轮 Agent 给出反馈或下一个问题后，当前 Run 正常结束，等待用户下一条普通输入。整场面试由多个 Run 组成，不让一个 Run 长期等待用户，不启动 Goal 自动代答。
- 「结束面试」提交一条明确的用户输入，请求基于已有问答复盘。运行中的取消继续走既有取消流程，取消本身不表示复盘已生成。
- 首版以用户约定的题数和主动结束为主。严格计时、到时提醒和自动中断需要宿主支持，不能由技能保证。

该入口采用现有 `chat` 会话，不要求绑定项目、Runner 或工作区。已有 coding 会话中提供「打开求职会话」入口，不因选择技能而隐式替换当前 Agent 的 system 或权限。首版只在使用非 coding 配置的普通聊天提供该技能，Spec 会话不提供选择，服务端同样校验适用场景。

### 5.2 技能与执行边界

| 项目 | 设计值 |
| --- | --- |
| 产品显示名 | 求职教练 |
| Agent 基础配置 | 基于 `chatProfile` 的非 coding 配置，由宿主明确选择 |
| 源文件名 | `career-coach/SKILL.md` |
| 内置运行时 ID | `nova.career-coach` |
| 首次版本 | `1.0.0` |
| 执行权限 | 首版创建时使用只读权限；技能选择不切换权限，前端不要求用户操作 Plan/Build |
| 必需工具 | 无；首版为纯文字分析与对话 |
| 工作区要求 | 无 |
| 交付形式 | 消息中的诊断、简历草稿、面试问题和复盘 |

宿主在创建会话时明确选择 Agent 配置并持久化标识。Agent 配置与 `chat/project` 会话归属、`plan/build` 执行权限是不同维度，不通过工作区有无或技能正文推断 Agent 身份。接受输入时固定本次配置版本或快照，进入现有队列和 checkpoint；活动 Run 内不更换配置。未携带新配置标识的既有会话维持原行为，避免上线时改变所有历史聊天。

非 coding 配置由宿主组装：

- 基础 system 采用 `chatProfile` 的中性职责与通用约束，不附加检查代码、实施变更、测试汇报等工作流。
- 首版工具集合为空，不注册文件、Shell、Git、工作计划、Spec 或 Goal 工具。后续需要文档能力时，由宿主增加明确的文档工具和策略。
- 执行权限保留服务端校验，但在该配置中使用中性的权限说明，不复用要求「implement the task」的 Build 文案，也不把只读权限解释成只能输出计划、不能改写简历文本。
- 不加载项目 `AGENTS.md`、Runner OS、Spec、Goal 的场景指令或计划文件门禁。只有明确进入相应运行场景时才由宿主安装。

现有 `CodingHarnessProfile` 只描述 `systemPrompt` 与可选 `plan`，工具和插件通过其他参数传入。因此切换一个 profile 字符串不足以完成上述组装。当前 `createCodingHarness` 支持显式 profile、无 Runner 和自定义工具，可以先复用这个装配入口，无需为本功能立即拆包或全仓改名。

技能文本描述工作方法，不注册工具或授予权限。技能选择、适用性与版本解析由服务端处理，再进入现有输入队列、checkpoint 和 Harness。恢复仍使用原 Agent 配置和技能版本；发布新版本后，旧版排队输入与恢复中的 Run 必须仍可解析原内容。服务端对技能与 Agent 配置的适用性分别校验，技能不能自行更换配置或扩大权限。

当前 `ComposerSkill` 对应 `/goal`、`/plan`、`/build`、`/spec` 等快捷命令。接入时区分宿主命令和产品技能，由服务端校验选择并使用插件注入正文，前端不把技能正文拼进用户输入来代替选择元数据。继续使用现有 Run API。

### 5.3 状态和材料

首版已有会话历史承载原始材料、用户补充、简历草稿与实际问答。经历摘要作为可见的对话工作摘要，不宣称建立了长期候选人档案。上下文被清除或关键材料缺失时，说明缺失并请求补充，不能假装仍然记得。

P0 不新建求职业务表。后续确实需要跨会话复用时，再新增求职领域模块，管理用户所属的经历档案、岗位目标、简历版本和面试记录；简历草稿继续从经历事实派生，不形成第二份经历事实源。个人材料按所有者授权读取，不因技能内置而成为共享数据。

当前上传存储主要支持图片，不能据此承诺 Word/PDF 简历输入；通用文件读取、解析、排版与发布需要各自验证。首版界面明确提示「粘贴简历和岗位描述」，结果支持复制。PDF/DOCX 输入与导出在文件能力完成后增加，导出复用通用产物链路。

### 5.4 代码落点与实施顺序

以下为 P0 已接入的位置；自建技能、文件产物与长期档案继续按后续阶段交付。

| 位置 | 责任 |
| --- | --- |
| `packages/tools/skills/career-coach/SKILL.md` | 内置求职方法正文 |
| `packages/tools/src/` | 按现有 `specSkill` 组织方式加载并导出技能资源 |
| `apps/nova-server/src/modules/skills/` | 登记内置技能、返回可选版本、解析选择；适用性由会话准入校验 |
| `packages/agent-ui-contracts/`、`modules/conversations/` | 明确的 Agent 配置标识、技能选择与展示契约、创建和追加输入时的校验 |
| `apps/nova-server/src/modules/runs/` | 按 Agent 配置组装基础 system、工具和插件；固定配置及技能版本进入 checkpoint，恢复原版本 |
| `apps/nova-client/src/features/conversations/` | 非 coding 会话入口、选择状态、任务建议、请求提交和结果展示 |
| `packages/chat-ui/` | 技能标签与菜单的展示和回调，网络与持久化继续由宿主负责 |

1. 在现有运行入口明确区分 coding 与非 coding Agent 的配置组装，隔离基础 system、工具和场景插件，并保留历史会话行为。
2. 完成通用技能选择、版本固定和运行注入的最小链路。可以先开放内置技能目录，自建技能编辑与资源包按通用设计分阶段交付。
3. 在非 coding 会话接入 `nova.career-coach`，交付粘贴简历、JD 定向修改和逐题文字面试。不依赖文件导出完成才能使用。
4. 文件能力就绪后接入简历解析与 PDF/DOCX 产物；出现实际需求后增加跨会话档案和训练记录。

不另建求职执行服务或工作流编排器。未来增加专用页面时，继续复用会话、Run、执行内核和该技能。

### 5.5 Nova 接入验收

- 求职入口创建非 coding 会话，最终模型请求中包含中性基础 system 与求职技能，不包含 coding、项目、Runner、Spec 或 Goal 的指令和工具。
- 未绑定工作区的非 coding 普通聊天可选中该技能并完成文本简历修改与面试；不会要求创建计划文件、检查仓库或运行测试。
- 面试连续回答时，每条输入都提交实际技能版本；未提交时不被服务端静默继承。
- 排队、取消、恢复和升级沿用通用 Run 语义；升级不改变已接受输入绑定的 Agent 配置和技能内容，旧会话保留原有运行行为。
- 一个问题输出后 Run 已结束，可以等待用户回答；结束面试后复盘只引用实际问答。
- 刷新后已有消息和采用的技能版本可查；清除上下文后不声称材料仍在当前上下文中。
- coding 与 Spec 会话不能从 UI 或直接请求注入该技能；文本版本不要求文件生成或工作区权限，技能内容也无法注册额外工具。
- 输入及展示契约从已有共享 schema 扩展，客户端继续生成；相关测试放在现有会话、运行和组件用例中。

## 6. 可用的 SKILL.md 正文

以下正文可独立使用。首版保持单文件，出现实际需要后再添加岗位参考材料或文档模板。

```markdown
---
name: career-coach
description: 根据真实经历和目标岗位修改简历，开展逐题模拟面试并复盘。适用于简历诊断、JD 定向改写、项目深挖及面试训练。
---

# 求职教练

帮助用户把真实经历表达清楚，并能在面试追问中解释简历中的主张。

## 选择任务

根据用户意图进入简历修改或模拟面试。用户同时需要两者时，先整理经历与简历，再围绕这些经历练习；用户明确要求先面试时照做。

沿用本次会话已有材料。只追问会改变当前结果的信息，不要求填完一整套问卷才开始。没有 JD 时可以做通用诊断，并说明定向建议的依据不足。

## 共用事实

从用户材料整理目标岗位、经历、个人贡献、行动与结果，保留信息来源。区分用户陈述、材料内容、推断和待确认信息；来源明确不等于独立验证。

不编造经历、年限、职级、技术栈、职责或成果数字。不把团队成果写成个人独立完成。材料冲突时指出冲突并询问，确认前不选择更有利的说法。

简历草稿和面试示例从经历事实派生，不能反向成为事实来源。用户纠正经历后，在后续两个模式中一致采用。参考答案不能当成用户已经掌握的证据。

## 简历修改

- 有 JD 时，把明确要求、偏好和未说明的信息分开，逐项对应经历证据；无 JD 时按目标岗位或通用表达问题诊断。
- 区分材料表达缺失与实际能力缺失，不因简历未写就断言用户不会。
- 优先解决岗位相关性、个人贡献和证据不足，再调整措辞与结构。根据用户要求选择局部改写或完整改写。
- 写清用户在什么场景负责什么、采取什么行动、产生什么结果。能量化则使用已有数据；没有数字时使用真实的定性结果，或询问如何验证。
- 给出主要问题、关键改写对照与理由，以及所需范围的草稿。把待确认信息单列，完整草稿不夹带假设成果。
- 指出重点改写可能引出的面试追问，让用户检查自己是否能解释每项主张。
- 岗位匹配判断附具体依据，不生成没有依据的 ATS 分数、录用概率或效果保证。

## 模拟面试

- 依据目标岗位、面试阶段和真实经历选择考察重点。必要时确认面试类型，用户背景已明确时直接开始。
- 默认陪练：回答及必要追问结束后反馈；用户要求仿真面试时，在结束后集中反馈。时长或题数沿用用户约定。
- 每轮只问一个问题，等待回答。围绕回答追问个人贡献、决策、替代方案、结果与复盘；技术深度适配目标岗位。
- 用户作答前不展示参考答案或暗示关键结论；用户要求提示、示范或跳过时响应，并区分辅助后的表现。
- 反馈引用本次回答的具体内容，按已体现、部分体现和尚未体现说明依据。技术错误与表达问题分别指出；无法判断的内容明确标注不确定。
- 不把自己设计的问题声称为某公司的真实面试题。涉及特定公司信息或变化较快的技术细节时，有可用可靠来源再核对，缺少依据时说明限制。
- 用户结束或达到约定范围时，依据实际问答给出优势、关键问题、基于真实经历的改进示例和下一步练习。参考示例中的未知经历用待补充说明，不代写成用户事实。
```
