# Chat、Project、Goal 与 SSH

## 使用入口

- 左侧 **新建 Chat** 创建普通会话；项目旁的 **+** 创建项目会话。会话页面不再切换聊天类型。
- **模型** 菜单按 Provider 分组，可搜索和收藏。模型与推理强度随每条消息传入服务端。
- **Plan** 只提供读取、目录和搜索工具；**Build** 提供修改和命令工具，并通过会话授权控件确认。
- 输入 `/goal 目标内容`，或点击目标图标后发送消息。可设置完成标准与总轮次上限，在目标卡片中暂停、继续、标记完成或移除。
- Goal 完成由 Agent 的 `finish_goal` 工具提交。达到上限、取消或执行失败时暂停，保留已提交结果。
- `/plan` 和 `/build` 切换模式；命令后接正文时使用该模式发送。
- 普通消息在运行期间进入队列。纯文本“调整方向”在下一次模型步骤生效；包含附件的消息使用普通队列。

## SSH 远程

在 **设置 → SSH 远程** 新建连接，填写主机、端口、用户名、绝对 POSIX 工作目录（默认 `/`）及密码或私钥。

1. 测试连接并确认实际主机指纹。
2. 完成认证和根目录验证后，在项目设置中绑定连接；Chat 输入框下方不再提供 SSH 选择或项目环境按钮，新会话的快捷任务也移除「连接 SSH」。
   普通 Chat 不再新选 SSH，旧草稿中的 SSH 选择会忽略；已有会话的远程配置、项目绑定和远程附件能力保留。
3. 可浏览目录、添加文本附件，使用远程读取、编辑与命令工具。
4. 目录预览、项目目录选择和附件选择从 `/` 开始，可访问 SSH 账号有权限访问的任意目录；已配置的工作目录只作为相对路径的基准，不限制浏览范围。
5. 项目目录和新选择的 SSH 附件保存绝对路径；已有相对路径仍按连接的工作目录解析。路径和文件摘要在服务端检查，文件变更后重新选择附件。

SSH 密码、私钥、私钥口令和模型 API Key 加密保存到服务端。前端只保留当前账号的配置偏好；旧版本的本地模型配置在首次使用时导入服务端。

提交 SSH 连接时，密码、私钥和私钥口令先封成 AES-256-GCM 传输信封（`enc1.<iv>.<tag>.<ct>`，十六进制），请求体里不出现明文；服务端解开后加密落库。传输密钥由服务端用调用方登录 token 派生的密钥加密下发，密钥本体不经过网络。

## 流式输出节奏

运行事件的持久化缓冲为 50ms，SSE 在有新事件时每 50ms 继续查询，空闲时逐步退避到 1 秒；客户端按 16ms 合并增量刷新。原先 SSE 固定每秒查询，加上 200ms 写入缓冲和 40ms 客户端合并，会让持续输出成批出现。缩短间隔会增加输出期间的数据库读写频率；实际输出节奏仍受模型、网络和数据库耗时影响。

## 本地运行

默认 `ROLE=all` 启动 API、Runner 连接和执行 Worker，适用于当前本地工作台。Runner 会话由该进程持有，使用 Runner 项目时保持这个模式。

新增数据库迁移：

- `0003_whole_mockingbird.sql`：SSH 连接及项目绑定字段。
- `0004_spooky_dazzler.sql`：持久化执行队列。

迁移已应用到当前本地数据库。其他环境需要运行 `pnpm --dir apps/nova-server db:migrate`。

在 Runner 设置创建 Token 后，填写工作目录并复制启动命令。当前仓库使用 Rust Runner：

```powershell
cargo run -p nova-runner -- --server 'ws://127.0.0.1:9203/runner/v1/connect' --token '<新生成的令牌>' --workspace '<你的项目目录>'
```

模型配置需要服务端 `MODEL_CONFIG_ENCRYPTION_KEY`，为 32 字节的十六进制密钥；已有加密数据依赖原密钥，不能随意更换。
